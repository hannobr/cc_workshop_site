CLAUDE.md and AGENTS.md.

~4 min · Reference; lives in ./CLAUDE.md

A · What they are

What is in the window before you type.

Every session starts with an empty context window. CLAUDE.md is what is already in it when you send your first word. Claude Code reads one from the current directory and from every directory above it, and concatenates what it finds rather than letting one file override another.

B · When to use them

When every session needs to know it.

Four honest triggers: Claude made the same mistake twice, a review caught something it should have known, you typed the same correction again, or a new teammate would need the same context.

Put it in CLAUDE.md

  • Build, test and run commands for this repo, in the form that actually works here.
  • Where things live: the layout a newcomer would otherwise have to reverse engineer.
  • Conventions that hold everywhere in the project.
  • An @AGENTS.md import, so one file serves every agent your team uses.
  • Standing workflow decisions: what to do without asking, what never to do unasked.

Reach for something else

  • Guidance for one folder. That is a path-based rule.
  • A multi-step procedure. That is a skill.
  • Something that must run at a fixed point. That is a hook.
  • Anything you would not want in every single session. It is loaded whether it is relevant or not.
  • A secret. It is committed, and it is read out loud into the model's context.

C · A real example

One brief, two kinds of agent.

A repo whose team already keeps an AGENTS.md for other tools, plus the few things Claude Code needs on top.

  1. 01A teammate on another tool edits AGENTS.md. Nothing here has to change.
  2. 02You start a session, and both files load before your first prompt.
  3. 03You ask for a change under src/billing/ and Claude opens plan mode without being reminded.
  4. 04You check /context and see exactly which memory files are loaded.

Two commands are worth knowing beside these files. /init can read existing Cursor and Copilot instruction files when it generates a CLAUDE.md, and /import appends a one-time copy of a file like AGENTS.md instead of importing it live. Both are generation steps; neither changes what is read at runtime.
