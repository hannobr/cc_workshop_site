Customise the harness  ·  Skills

Skills.

A folder of instructions Claude loads by itself when the work matches. A skill is the answer to “I keep pasting the same procedure into the chat”, and since 2026 it is also what a custom slash command is.

~4 min · Reference; lives in .claude/skills/

A · What they are

A folder Claude opens only when it needs to.

A skill is a directory holding a SKILL.md: YAML frontmatter on top, your instructions under it. Claude does not read the instructions at startup. It reads one line, the description, and opens the rest when the work in front of it matches.

You do not have to write one by hand. Hand a finished run to /skill-creator and rule on what generalises.

B · When to use them

When a procedure keeps repeating.

A skill is for something you do more than once and want done the same way each time.

Reach for a skill

  • A checklist you keep pasting: how a release goes out, how a page gets verified.
  • A section of CLAUDE.md that grew into a procedure rather than a fact.
  • Reference material a house style, an API convention, that only matters sometimes.
  • A command you want to trigger yourself, with disable-model-invocation.
  • Work you want handed to a subagent, with context: fork in the frontmatter.

Reach for something else

  • A single fact. That belongs in CLAUDE.md.
  • A convention tied to one folder. That is a path-based rule.
  • Something that must happen every time. That is a hook.
  • A guidelines-only skill with context: fork. The fork gets no task and returns nothing.
  • A SKILL.md over about 500 lines. Push the detail into files beside it.

C · A real example

A skill that reviews your own diff.

Anthropic's own getting-started example, and a good first skill because it shows the one trick that makes skills feel alive.

  1. 01You finish an afternoon of edits and type “what did I change?”.
  2. 02The description matches, so Claude loads the skill without being told to. Typing /summarize-changes does the same thing on purpose.
  3. 03The harness runs git diff HEAD and pastes the real diff into the skill body.
  4. 04You get three bullets and a risk list, in the same shape, every time you ask.

Once a skill exists, it is a file in git like any other. The review that matters is not “is this prompt nice” but does the description fire when it should and stay quiet when it should not.
