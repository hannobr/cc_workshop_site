Customise the harness  ·  Path-based rules

Path-based rules.

Guidance that loads only when the files it covers are touched. A rule is how a convention that matters in one folder stays out of every session that never goes near it.

~3 min · Reference; lives in .claude/rules/

A · What they are

Guidance that waits for its own folder.

A rule is a markdown file under .claude/rules/, one topic per file. Give it a paths: list of globs and it stays out of the context window until Claude reads a file that matches. The trigger is reading a matching file, not every tool call.

B · When to use them

When the advice is true here and wrong elsewhere.

Ask where the guidance applies. Everywhere is CLAUDE.md. One corner of the repo is a rule.

Reach for a rule

  • Conventions for one area: API handlers, migrations, tests, one package in a monorepo.
  • A CLAUDE.md that has got long and is mostly about places most sessions never go.
  • House style for a file type, scoped with a glob like src/**/*.tsx.
  • Guidance you want in context automatically, without anyone remembering to load it.

Reach for something else

  • A fact every session needs. That is CLAUDE.md.
  • A multi-step procedure. That is a skill.
  • Anything that must be enforced. That is a hook.
  • A pattern starting with [, unescaped. It is read as a character class and matches nothing.

C · A real example

Test conventions that arrive with the tests.

The root CLAUDE.md says nothing about tests. This file does, and only when it is relevant.

  1. 01A session opens src/billing/invoice.ts. This rule stays out of context entirely.
  2. 02Later the same session opens tests/billing/invoice.test.ts.
  3. 03The rule loads at that moment, and the factory convention is in context exactly when it is actionable.
  4. 04The test comes back using makeUser() without anyone having said so this session.

Two things that look like bugs and are not. After a /compact a path-scoped rule reloads only when a matching file is read again, so it can look absent. And if you want to see exactly what loaded and when, the documented tool is the InstructionsLoaded hook, which fires every time a CLAUDE.md or a rule file enters context.
