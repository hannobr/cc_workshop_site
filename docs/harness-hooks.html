Customise the harness  ·  Hooks

Hooks.

Your own commands, run by the harness at fixed points in the loop. A hook is the only customisation on this site that does not depend on Claude deciding to do something: the harness runs it either way.

~4 min · Reference; lives in .claude/settings.json

A · What they are

Your command, wired into the loop.

Claude Code runs a loop: you send a prompt, the model calls a tool, the tool returns, the model tries to finish. A hook is a command of yours registered at one of those points. The harness runs it. Nothing in the conversation gets a vote on whether it happens.

B · When to use them

When asking nicely is not enough.

The test is whether you would accept the thing being skipped. If you would, write it down instead. If you would not, hook it.

Reach for a hook

  • Format or lint after every edit, so style never becomes a review topic.
  • Block a path such as .env or a production config, whatever the session thinks.
  • Run the test suite before Claude is allowed to stop, and hand back the failure.
  • Inject context on every prompt: the current ticket, the branch, the on-call name.
  • Log or notify: desktop ping when a long run finishes, an audit line per tool call.

Reach for something else

  • A convention or a preference. That is CLAUDE.md.
  • A convention for one part of the tree. That is a path-based rule.
  • A procedure Claude should choose to run. That is a skill.
  • Anything needing judgment about the content. A shell script cannot read intent.
  • Slow work on a hot event. Every PreToolUse hook is on the critical path.

C · A real example

Prettier on everything Claude writes.

A front-end repo where formatting arguments were eating review time. One hook ends them.

  1. 01You ask for a new component. Claude writes it with single quotes and a stray trailing comma.
  2. 02The Write call returns, and the harness fires PostToolUse because the matcher Edit|Write hit.
  3. 03Prettier rewrites the file in place. On success nothing appears in the conversation.
  4. 04The diff you review is already formatted, on the first pass, with no line in CLAUDE.md asking for it.

One sharp edge worth knowing: this fires on the Edit and Write tools only. If Claude rewrites the file through a Bash command, the matcher never hits. To catch a file however it changes, hook FileChanged instead.
