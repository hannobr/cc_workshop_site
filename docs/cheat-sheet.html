A · Stop, undo, restart

When Claude goes the wrong way.

Three escape hatches, each cheaper than starting over. Use them often.

Esc Shortcut

Interrupts the current response or tool call mid-stream; Claude keeps the work done so far [1]. Hit it the moment Claude starts down the wrong path, then send a follow-up with what you learned.

Esc Esc Shortcut

On an empty prompt, double-Esc opens the rewind menu. Pick a previous point to jump back to, and choose whether to restore the conversation, the code, or both. Cheaper than stacking corrections on a wrong run.

TRYempty prompt: press Esc twice
/clear Slash

Wipe the conversation and start over without killing Claude Code itself [2]. The new conversation starts empty and reads CLAUDE.md fresh [7]. Faster than /exit + relaunch.

B · Steer Claude

Set the mode. Watch the window.

Know which mode you're in and how full the context window is. Most confusing sessions trace back to one of the two.

Shift+Tab Shortcut

Sessions in this workshop start in auto mode: Claude edits files and runs routine commands without stopping to ask, with a built-in safety check on the risky ones [3]. Shift+Tab cycles the four modes: manual, accept edits, plan, auto. Tap until the status bar names the one you want; the build in step 04 starts in plan mode.

/plan Slash

Jump straight into plan mode for the next prompt [3]. Claude reads, explores, and writes a plan. No edits until you approve. Use before any change where you want to see the approach before the edits.

TRYrunnable today: › /plan outline the smallest first version of my idea
/context Slash

Visualize the current context window as a color grid: system prompt, memory, tool output, conversation, free space [2]. Your first stop when something feels slow or off.

/compact Slash

Summarize the conversation so far and free the window [2]. The habit: compact at a natural break, with intent. Add a focus hint after the command so the summary keeps what matters.

TRYat a natural break: › /compact keep the API design decisions

C · In the prompt

Five tricks that fit inside your prompt.

You type these inside the prompt. Each one changes how Claude reads what comes next.

@file Inline

Type @ then start typing a path; autocomplete does the rest [1]. Mentioned files load into context, no copy-paste needed.

› what does @src/auth/login.ts use for session storage?
!cmd Inline

Prefix with ! on an empty prompt to run a shell command. The output joins the session and Claude responds to it on the spot [1]; set respondToBashCommands to false for output only.

› !git status · output lands, Claude responds
Ctrl+G Shortcut

Opens the current prompt in $EDITOR [1]. Save & close to send. Use it when the prompt is more than you want to edit inside a terminal. vim or code beats the terminal for anything structured.

/btw Slash

Ask a side question without adding to history [1]. Works even while Claude is processing. No tool access, answers only from what's already in context. Dismiss with Space, Enter, or Esc.

TRYwhile Claude is generating: › /btw what was that env var called again?
/ Discover

Type / on an empty prompt to see every command available in your setup [2]: built-ins, plugins, MCP, skills. Filter by typing more letters. This is how you find anything not on this page.

D · Customize

The moves behind the build steps.

Skills, subagents, rules, the /goal finish line and hooks all turn up while you build; headless mode and MCP are parked here for after the workshop.

/skill-name Skills

A folder at .claude/skills/<name>/SKILL.md becomes the command /<name>. Claude also uses skills on its own when relevant [4]. Write one for a convention or a procedure you want applied the same way every session; a one-line repo fact belongs in CLAUDE.md, a one-off instruction stays in the prompt, and a choice about only the next feature stays in the spec.

@agent Subagents

Subagents are Markdown files in .claude/agents/ with their own context window. Type @ and pick one from the typeahead, or address it as @agent-<name> [5]. The usual first one is a verifier: it runs the check and reports, and cannot edit.

.claude/rules/ Rules

Rule files with a paths: glob in the frontmatter load only when Claude reads a matching file [7]. The overflow valve that keeps CLAUDE.md short: a nested CLAUDE.md is scoped by directory and has to live there, a rule is scoped by glob and can cover a flat repo from one file.

/goal Verify

Set the finish line for this session: a check Claude can run, named by the command that proves it [10]. After every turn a second, smaller model reads the transcript and decides whether the condition is met. If not, Claude keeps working. The judge does not run commands itself, so the condition has to name the command and what its output shows. Add what must not change and a turn cap. A hook is the same check made permanent for every session.

TRYin auto mode, once the plan is approved: › /goal the tests pass and a playwright-cli run shows the first screen working. No test file changes. Stop after 15 turns.
hooks Guardrail

Scripts registered in .claude/settings.json that run before a tool call and can refuse it; exit 2 blocks [8]. Deterministic where a skill and CLAUDE.md are advisory: the harness runs a hook, so it is the one place you force a check rather than ask for it. Reach for it once you know the check is the one you want.

claude -p Headless

One non-interactive pass from your shell. --allowedTools grants tools up front; -p starts in manual mode on every plan, so grant what the run needs [9].

/mcp MCP

Lists connected MCP servers, their status, and their tool counts [6]. Add one from your shell with claude mcp add <name> -- <command>.
