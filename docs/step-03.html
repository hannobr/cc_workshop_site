03  ·  Context window

Make your context window visible.

You'll paste one spec into Claude Code. It configures a custom statusline through /statusline, so the bottom of your terminal shows how full your context window is for the rest of the day.

~5 min · One task, one spec

Start here

Paste first, read after

Switch Claude Code to auto mode, then copy the prompt in section A and press Return. You do not need to understand the prompt yet. It runs for a few minutes, and section B explains what it is measuring while you wait.

→
Shift + Tab until the status bar reads auto mode on
A

Paste the spec

Copy the whole prompt and press Return. Claude reads the statusline docs [1], writes the script, tests it at three fill levels, and then shows you what it built. Leave it running and read section B.

FULL SPEC … lines · … chars 
Read https://code.claude.com/docs/en/statusline first.
Configure my statusline via /statusline. Single line, segments separated
by │, left to right:

Model display name in [brackets]
Context bar: ▓▓▓▓▓░░░░░ 47%. 10 chars, filled blocks = used context,
rounded to nearest block. Color rules apply to filled blocks only; empty
stays dim grey:

< 30% → green
30%–70% → amber
> 70% → red


Git branch (omit this segment entirely when not in a git repo)
Session cost formatted as $0.42 (two decimals)

Pull from model.display_name, context_window.used_percentage (treat null
as 0), and cost.total_cost_usd. Use git directly for the branch.
The context bar is the focal point. It should be the only colored
element on the line so my eye lands on it. A glance should tell me how
full I am, not how empty.
After installing, verify with mocked stdin at 15%, 50%, and 85% to
confirm the color thresholds work, then show me the final script.
▲ Copy with the button above, paste into Claude, press Return.
B

What the gauge measures

Claude is working now. The number you are about to see on your status bar is how much of one shared context window the session has used: the system prompt, CLAUDE.md, the conversation, every tool call and every file Claude reads. On the default model that window caps at one million tokens, and answer quality can degrade well before the cap [2]. As a rule of thumb, keep it under 50% [3].

Two commands give the room back, and they cost you different things.

Pass check

Your statusline shows the current model, a live context-fill percentage, the branch name (if it is a git repo) and the cost for the session so far.

Missed? Tell Claude what it did wrong and copy paste the spec again in Claude Code.

Passed? The gauge rides along for the rest of the day; when it climbs past 50%, /clear between tasks, and /compact with a hint only where the thread has to survive. Then the break: the room talks the next steps through before the build starts.
